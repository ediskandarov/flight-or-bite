## 10. Ограничения и отклонения

- G6 не пройдены: «выводы зависят от ручных параметров» (раздел 6).
- В основном эксперименте Jev вызывался через alpha-эндпоинт OpenRouter Decisions; `t_wall` Jev включает этот переход (D12). Прямой TypeSafe API измерен отдельно (D63–D64).
- Таблицы политик Jev и LIF-симуляции коннектома строил агент из своего процесса; их `t_wall` не является замером по протоколу (используется только в анализе H6 для Jev). Замеры раздела 8.1 и главный прогон выполнял автор (D5).
- Отклонения от SPEC перечислены в `docs/decisions.md` (D1–D64), ручные допущения — в `docs/ENGINEERED.md`.
- Расход вызовов Jev: 80580 из 100000.
- Обращений к тестовому сплиту (строк `runs/test_access.log`): 2000.

Прочтения там, где PREREG молчит (зафиксированы коммитом до просмотра таблиц и тестовых результатов):

- RQ3, срезы для логистического фита: `p_escape(looming)` при sugar = 0, bitter = 0, hunger = 0.5; `p_eat(bitter)` при sugar = 0.667 (узел сетки, ближайший к 0.6), looming = 0, hunger = 0.5. Фит p = 1 / (1 + exp(−k·(x − x0))) методом наименьших квадратов по узлам; порог = x0, крутизна = k. Для детерминированного оракула фит вырожден: приводится середина между узлами, где решение меняется.
- RQ3, дивергенция Дженсена—Шеннона: по основанию 2, между политиками в узле (средними по повторам), невзвешенное среднее по 1 225 узлам сетки B.
- RQ4: прогноз — `probabilities[ESCAPE]` каждого повтора в каждом узле (копии в бакетных режимах включены: узлы разные, метка оракула у каждого своя); исход — «ESCAPE оптимально по оракулу» в узле; reliability-таблица — 10 равных интервалов вероятности.
- H6, Jev: как и у коннектома, ρ Спирмена считается между d в узле (по политике самого Jev) и медианой `t_wall` в узле, бутстреп по узлам; ρ по отдельным вызовам приводится дополнительно и в критерий не входит.
- Рисунок «скорость против качества»: ДИ по оси X — бутстреп p50 по решениям (2 000 ресэмплов), по оси Y — бутстреп `% от оракула` по эпизодам (сиды ресэмплируются совместно для всех арбитров).
- «Цена решения» (SPEC §7): среднее `t_wall` на решение и суммарное `t_wall` на эпизод в главном прогоне.
